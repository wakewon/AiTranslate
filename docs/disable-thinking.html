进阶：如何为模型“关闭思考”？

按模型和请求端点选择参数，关闭思考或降低推理强度

1. 什么是请求头和请求体？

AiTranslate 插件支持在 Bob 配置界面的高级设置中注入 额外请求头 (Headers)、额外查询参数 (Query) 和 额外请求体 (Body)。它们都接收合法的 JSON 格式字符串。

对于关闭深度思考（思维链）这种操作，几乎都是通过修改“请求体 (Body)”来实现的，因为这属于修改发给模型的具体指令参数。

你可以使用我们提供的 参数构建工具，快速生成所需的 JSON 字符串，然后复制粘贴到 Bob 的「额外请求体」输入框中即可。

服务密钥和鉴权应按实际端点单独配置。查看各服务的鉴权方式

2. 各大平台关闭思考的 JSON 模板

适用服务商 / 模型 所需的 JSON 结构（填入额外请求体） 说明
DeepSeek 官方 Chat Completions { "thinking": { "type": "disabled" } } 适用于官方文档列出的模型和端点。DeepSeek 思考模式
OpenAI Chat Completions { "reasoning_effort": "none" } 使用顶层 reasoning_effort。只有支持 none 的模型才可用这个值。Chat Completions 参数
OpenAI Responses { "reasoning": { "effort": "none" } } gpt-6-luna 支持 none。gpt-6-astra 和 gpt-6.1-sol 的最低档位为 low。OpenAI 推理指南
智谱 GLM-5.3 Chat Completions { "thinking": { "type": "enabled" }, "reasoning_effort": "low" } 思考始终开启，low 是最低档位。GLM-5.3 模型文档
通义千问 / 阿里云百炼 { "enable_thinking": false } 适用于支持关闭思考的混合思考模型。百炼思考模式
Ollama OpenAI 兼容 Chat Completions { "reasoning_effort": "none" } 实际效果取决于模型支持的档位。原生 /api/chat 的参数需单独核对。Ollama 兼容接口
