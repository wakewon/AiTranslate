让翻译少等一会儿

有些模型在写出译文前会先花时间思考。平时只查一个词、翻一句短句，如果等待太久，可以试试调低思考等级。已经能很快看到译文的话，沿用默认设置就好。

先找你的翻译服务

看看 Bob「Ai 翻译」中填的是哪个模型、用的是哪家服务。展开下面对应的说明，可以查到这个模型能否关闭思考，或调到较低的档位。

使用 Gemini 的话，配置助手能按模型列出可选等级。选好后复制生成的设置，粘贴到 Bob 的「额外请求体 (JSON)」。如果这里已经有内容，先留一份副本，方便恢复。在配置助手里选 Gemini 思考等级

查看我用的服务

DeepSeek

通过 DeepSeek 官方 Chat Completions 使用支持思考开关的模型时，将 thinking.type 设为 disabled。DeepSeek 思考模式

{"thinking": {"type": "disabled"}}
OpenAI

先看 Bob 中的「请求格式」，Responses 与 Chat Completions 的写法不同。例如，要使用 low 档位，先确认模型支持该值，再选择对应的写法。支持 none 的模型可以把值改为 none。OpenAI 推理指南

Responses API

{"reasoning": {"effort": "low"}}

Chat Completions

{"reasoning_effort": "low"}
Google Gemini

选择「Gemini generateContent」和实际使用的模型。如果「JSON 参数」显示「当前模型的思考等级」，选中需要的档位，再把生成的 JSON 复制到 Bob 的「额外请求体」。例如，gemini-4-hydrogen 可以用 low 降低推理强度。

{"generationConfig": {"thinkingConfig": {"thinkingLevel": "low"}}}

Gemini 2.5 系列用 thinkingBudget 控制推理预算，允许的范围因型号而异。Google 思考参数说明 · 配置 Gemini 参数

通义千问（阿里云百炼）

通过百炼的 OpenAI 兼容 Chat Completions 使用支持此开关的混合思考模型时，可将 enable_thinking 设为 false。百炼深度思考说明

{"enable_thinking": false}
智谱（GLM-5.3）

GLM-5.3 始终启用思考。要减少推理量，可以选择其最低档位 low。GLM-5.3 参数说明

{"thinking": {"type": "enabled"}, "reasoning_effort": "low"}
本地 Ollama

使用 OpenAI 兼容接口时，先从本地服务的 /api/show 查看模型支持的推理档位。兼容接口可用 reasoning_effort，none 的实际效果取决于模型，例如 GPT-OSS 会按最低档位运行。Ollama 兼容接口

没有看到自己的服务？在配置助手中填入服务商和模型名称，复制生成的问题，请能联网的 AI 助手帮你查官方说明。帮我写一段查询问题

用同一句话再试一次

保存设置，翻译之前试过的同一句话，看看等待时间和译文是否合适。如果翻译报错，先移除刚添加的字段，或把之前留存的内容粘贴回去，再点击「保存」。

想确认模型是否真的减少了思考

有些服务会在控制台记录每次请求的思考用量。找到本次翻译，对比调整前后的推理 Token 数。如果返回 400 错误，核对报错中提到的参数名和可用取值。

官方文档里有 extra_body，怎样复制？

有些 SDK 把自定义字段放在 extra_body 中。Bob 的「额外请求体 (JSON)」只需要里面的字段。如果已经设置了其他参数，把它们合并在同一对花括号内。编辑额外请求参数
