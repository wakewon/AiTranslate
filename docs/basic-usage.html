在 Bob 里翻译第一句话

下面用 bilibili 翻译做一次设置。它目前可以免密钥使用。已经有其他服务的密钥，或已经在 Mac 上运行了模型，也可以用自己的服务完成这几步。

1把插件加到 Bob

如果 Mac 上还没有 Bob，请先从官网安装并打开。已安装的 Bob 需要 1.8.0 或更高版本。获取 Bob

下载 AiTranslate 后，双击下载好的 .bobplugin 文件安装。如果打开的是 GitHub 发布页，安装包在「Assets」下方。下载插件安装包

打开 Bob「偏好设置 → 翻译 → 服务」，选中「文本翻译」。点列表下方的加号，选择刚安装的「Ai 翻译」。让这个窗口保持打开，稍后在这里填写。

2选一个翻译服务

第一次试用可以直接打开 bilibili 的配置助手。页面已经选好了服务和模型，模型就是实际负责翻译的程序。

打开 bilibili 的配置

我想用 DeepSeek 或其他云服务

云服务通常会给你一串专用密钥，叫做 API Key，用来确认这次翻译属于哪个账号。登录服务商的开发者平台，在「API Keys」或「密钥管理」里创建并复制密钥。例如，DeepSeek 可以从这里申请。DeepSeek 密钥管理

在配置助手中选同一家服务商，再选你账号能用的模型。密钥只需填在 Bob 里。打开 DeepSeek 配置 · 查找其他服务商

我想用 Mac 上已经下载的模型

先启动本地服务。用 Ollama 的话，在终端运行 ollama list，从 NAME 列复制模型名称（包括冒号后的标签）。用 LM Studio 的话，在 Developer 页启动服务器，复制要使用的模型标识符。把名称填进对应的配置助手。默认本机服务可以留空 API Key。配置 Ollama · 配置 LM Studio

3把设置填回 Bob

对照助手里的「在 Bob 中填写」，回到刚才的「Ai 翻译」窗口。把服务地址（Base URL）和模型复制到同名输入框，需要改的下拉选项按助手给出的名称选择。

以 bilibili 为例，Base URL 填 https://index-translate.bilibili.com，模型填写助手选中的名称，API Key 留空。如果选的是需要密钥的服务，在这里粘贴刚才申请的密钥。其余设置可以先用默认值。

4试译一句话

在 Bob 点击「验证」。看到成功提示后，开启这项服务并点击「保存」。打开翻译窗口，选「简体中文」作为目标语言，输入 See you tomorrow. 后按回车。如果「Ai 翻译」显示「明天见」或意思相近的译文，就设置好了。

没有看到译文？

加号菜单里找不到「Ai 翻译」

在 Bob 的「偏好设置 → 插件」中确认已安装「Ai 翻译」。回到「翻译 → 服务」，选中「文本翻译」再点加号。Bob 插件安装图解

验证时提示密钥无效（401 或 403）

从申请密钥的平台重新复制一次，确认 Bob 中选的是同一家服务、账号也能使用这个模型。再按配置助手的建议选择「鉴权方式」。

提示找不到模型或地址（404）

从配置助手重新复制地址和模型名称。使用公司或本地服务时，向提供服务的人确认当前可用的模型。

验证通过，翻译时提示「流式响应为空」

「验证」使用非流式请求。先关闭「流式输出」再翻译同一句话。如果这样能收到译文，请核对端点的流式接口和代理的 SSE 支持。

译文里出现了 ** 或 # 这样的符号

Bob 1.21.0 及以上搭配 macOS 13 及以上可以渲染 Markdown。检查插件里的「Markdown 渲染」和 Bob 的「偏好设置 → 翻译 → Markdown」。较早的版本会按纯文本显示。需要纯文本译文时，也可以在系统指令中指定。Bob 的 Markdown 支持说明

怎样让译文保留术语、代码和段落？

插件已有默认翻译指令。需要保留术语、代码或 Markdown 结构时，可以把固定要求写在「自定义系统指令」里。下面是一组翻译技术文档的示例。

自定义系统指令

你是技术文档译者。保留代码、变量名和 Markdown 结构，只输出译文。

自定义用户指令

请将下面的 $sourceLang 原文译成 $targetLang。

$text

插件会把 $text 换成选中的原文，把两个语言变量换成 Bob 提供的语言名称。自行填写用户指令时记得保留 $text。在配置助手生成翻译指令

账号或本地服务器里要复制哪个模型名称？

到实际提供 API 的平台查 ID，再把它完整复制到「模型」。同一个模型在不同平台可能有不同的名称。

云端 API
在服务商控制台确认该模型支持文本生成，且已向你的账号、项目和地区开放。从目录查官方文档
Azure OpenAI
填资源中自定义的部署名称。可以在部署详情中复制。Microsoft 部署说明
本地服务
Ollama 填 ollama list 列出的名称，保留冒号后的标签。LM Studio、vLLM 等服务填当前服务器提供的模型 ID。LM Studio 模型列表
服务地址和接口路径应怎么区分？

在服务商文档里找到发送请求的网址。以 OpenAI 的 https://api.openai.com/v1/chat/completions 为例，「Base URL」填 https://api.openai.com，选择 Chat Completions 后，插件会补上后半段路径。

如果服务商用的路径不同，在「端点路径覆盖」中填写从 / 开始的完整路径。插件会将它直接接在 Base URL 后面。把 /v1 同时写进这两个字段会导致地址重复。

查看七种请求格式的默认路径
Bob 中的请求格式默认路径
OpenAI Chat Completions（通用兼容）/v1/chat/completions
OpenAI Responses API/v1/responses
OpenAI Legacy Completions/v1/completions
Anthropic Claude Messages/v1/messages
Anthropic OpenAI 兼容/v1/chat/completions
Gemini generateContent按模型和流式开关生成，见下文
Gemini OpenAI 兼容/v1beta/openai/chat/completions
其他兼容服务怎么填？

Together AI 的 Chat Completions 可以使用默认格式，Base URL 填 https://api.together.ai。模型名称通常包含提供方前缀，要从 Together 当前的模型列表完整复制。Together AI 接口说明

使用 DeepSeek 的 Anthropic 兼容接口时，选择「Anthropic Claude Messages」，Base URL 填 https://api.deepseek.com，端点路径覆盖填 /anthropic/v1/messages。DeepSeek 的 Anthropic 接口

使用 vLLM、llama.cpp 或 LocalAI 自建服务时，先确认服务器提供的接口和模型 ID。在配置助手的「自定义服务商」中填入实际地址，就可以生成配置查询提示词。查询自定义配置

Gemini 的模型名称填在哪里？

选择「Gemini generateContent」，Base URL 填 https://generativelanguage.googleapis.com，「端点路径覆盖」留空。在「模型」里填写模型 ID，省略 models/ 前缀。插件会构造 /v1beta/models/{model}:generateContent，开启流式时自动改用 :streamGenerateContent?alt=sse。

如果代理要求你手填路径，请把 {model} 换成实际 ID，并选择与流式开关对应的接口。插件会原样发送这条路径。Gemini 接口文档

服务商要求指定发送密钥的方式，怎么选？

通常保留「自动（按请求格式）」，在「API Key」里粘贴原始密钥。插件对 Gemini 原生接口使用 x-goog-api-key，对其他六种格式添加 Authorization: Bearer 请求头。

服务商指定了其他请求头或 URL 参数

按接口要求，在「鉴权方式」里选择 x-api-key、x-goog-api-key、api-key 或 URL 查询参数 key。例如，Azure 用资源密钥时选 api-key，用 Microsoft Entra 访问令牌时选 Bearer。Azure 鉴权说明

使用 Claude 的跨工作区密钥时，在「额外请求头」填写目标工作区的 anthropic-workspace-id。Claude 鉴权说明

本地 Ollama 或 LM Studio 需要填密钥吗？

直连默认的本地 Ollama 或 LM Studio 时，「API Key」留空即可。LM Studio 开启鉴权后要填服务器签发的令牌。经代理访问时要看代理的设置，直连 Ollama Cloud 则要填云端密钥。Ollama 鉴权 · LM Studio 鉴权

已经在额外字段里配置了凭据

自动模式遇到已有的标准鉴权头或查询参数 key 时，会沿用你提供的值。若服务用自定义名称，可选「手动或无需鉴权」，再填写额外请求头或额外查询参数。请求头名称不区分大小写。留空「API Key」也会跳过自动鉴权。
