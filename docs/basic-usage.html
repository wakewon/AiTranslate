基础使用教程

从零开始，教你如何接入任意 AI 翻译服务

快速安装与启用

  1. 在 GitHub Releases 下载最新的 .bobplugin 文件并双击安装。
  2. 在 Bob 的设置 -> 服务 -> 文本翻译中，点击左下角 + 号，添加 Ai 翻译。
  3. 根据实际调用的端点，在插件设置中选择对应的 请求格式。服务提供 OpenAI 兼容 Chat Completions 时，可选默认的 OpenAI Chat 格式。
  4. 在 Base URL 中填写服务根地址。插件会按请求格式添加端点，例如 /v1/chat/completions。根据实际端点选择 鉴权方式，并按服务要求填写有效密钥。无需鉴权的服务可留空。查看各服务的鉴权要求
  5. 在 模型 中填写当前端点支持的模型 ID。Azure OpenAI 填部署名，自托管服务填本机已加载或已部署的 ID。查看模型 ID 示例
  6. (可选) 您可以打开高级参数构建工具生成个性化参数（如关闭思考等）并粘贴到插件底部的“额外请求体”中。更多进阶玩法请访问文档中心阅读。

1. 请求格式怎么选？

本插件支持 7 种细分的 API 请求格式选项，它们决定了插件如何与大模型通信：

  • OpenAI Chat Completions（通用兼容）: 最通用的格式，绝大多数国产模型（DeepSeek、Kimi、豆包、智谱等）和第三方中转站（硅基流动、OpenRouter）都兼容此格式。
  • OpenAI Responses API: 适用于 OpenAI GPT-6 系列等支持 Responses 的模型。
  • OpenAI Legacy Completions: 老旧模型或部分遗留系统的单轮对话格式。
  • Anthropic Claude Messages: Claude 官方原生端点专用。
  • Anthropic OpenAI 兼容: 部分基于 Anthropic 但提供 OpenAI 兼容接口的服务。
  • Gemini generateContent: 谷歌 Gemini 官方原生端点专用。
  • Gemini OpenAI 兼容: 部分基于 Gemini 但提供 OpenAI 兼容接口的服务。

2. Base URL 和端点（Endpoint）填写指南

Base URL (基础网址) 是服务商的根地址。端点 (Endpoint) 则是具体的接口路径。根据不同的 API 格式，插件会自动拼接路径，但有时你需要自己手动调整端点：

案例 A：DeepSeek 官方 API

参考文档：DeepSeek 官方文档

  • 请求格式： OpenAI Chat Completions
  • Base URL： https://api.deepseek.com （不要带 /v1）
  • 自定义端点： 留空 （插件默认使用的请求格式会自动补充 /v1/chat/completions）

案例 B：Google Gemini 原生 API

Gemini 原生接口把模型 ID 放在 URL 路径里。官方文档中的 {model} 表示实际模型 ID。Gemini 端点文档

  • 「请求格式」选 Gemini generateContent，「Base URL」填 https://generativelanguage.googleapis.com。
  • 使用默认端点时，「端点路径覆盖」留空，在「模型」中只填实际 ID，例如 gemini-3.8-flash。插件会自动加上 models/ 前缀，拼出 /v1beta/models/gemini-3.8-flash:generateContent。开启流式时，使用 :streamGenerateContent?alt=sse。如果「模型」也留空，当前内置值为 gemini-2.5-flash。
  • 手动覆盖端点时，直接填写包含实际模型 ID 的完整路径，例如 /v1beta/models/gemini-3.8-flash:generateContent。插件按原样使用覆盖路径，{model} 不会被替换。请求使用路径中的模型，流式开关也不会改写该路径。

案例 C：智谱 GLM 官方 API（特殊后缀）

智谱的 Chat Completions 使用自定义路径。智谱官方文档

  • 请求格式： OpenAI Chat Completions
  • Base URL： https://open.bigmodel.cn
  • 自定义端点： /api/paas/v4/chat/completions（填写后，插件将不再自动补充路径，而是完全使用你填写的端点）

OpenRouter 和 Groq 也需要覆盖端点路径。OpenRouter 使用 /api/v1/chat/completions，Groq 使用 /openai/v1/chat/completions。OpenRouter · Groq

3. 鉴权方式和 API Key 怎么填？

  • 通常选「自动」。填写有效 API Key 后，Gemini 原生用 x-goog-api-key，其余格式用 Bearer。
  • 无需鉴权才直接留空。默认的本地 Ollama 和 LM Studio 无需占位密钥。下列官方云端接口和启用了鉴权的代理需要有效凭据。
  • 端点要求其他方式时，在「鉴权方式」里指定请求头或 URL 参数，例如 Azure 资源密钥可选 api-key。自行配置凭据时可把 API Key 留空。
逐家鉴权对照与官方来源

本地和自托管接口

  • Ollama 本地直连 http://localhost:11434 时留空即可。官方 SDK 示例里的 api_key="ollama" 只用于构造 OpenAI SDK 客户端，同页的 HTTP 示例直接省略鉴权头。用本地 Ollama 登录并转发云模型时，插件仍连接本地端口。鉴权 · OpenAI 兼容接口
  • LM Studio默认关闭鉴权，可以留空。服务器开启 Require Authentication 后，填 LM Studio 生成的 API Token，使用 Bearer。LM Studio 鉴权
  • vLLM 和 llama.cpp未配置服务端密钥时可以留空。启动时配置了 --api-key 或等效设置，就给插件填真实密钥，使用 Bearer。vLLM 启动选项 · vLLM 请求示例 · llama.cpp
  • LocalAI两种服务端鉴权都未开启时可以留空。启用 API Key 鉴权时，填有效密钥，使用 Bearer 或服务支持的 x-api-key。LocalAI 鉴权

经由反向代理、托管平台或私有网关访问时，以该入口的鉴权规则为准。入口要求密钥时，使用有效凭据。

官方托管推理接口

  • OpenAI使用有效 API Key 或访问令牌，通过 Bearer 发送。OpenAI 鉴权
  • Anthropic Claude原生 Messages 推荐 Bearer，也支持旧版 x-api-key。OpenAI 兼容接口使用 Bearer。跨工作区密钥需要额外的 anthropic-workspace-id。Claude 鉴权 · OpenAI 兼容接口
  • Google Gemini原生 generateContent 用有效密钥和 x-goog-api-key。OpenAI 兼容端点 /v1beta/openai/chat/completions 用 Bearer。只有目标端点明确支持通过 URL 收密钥时才选查询参数 key。Gemini 原生接口 · OpenAI 兼容接口
  • Azure OpenAI使用资源 API Key 时，可选 api-key。使用 Microsoft Entra ID 时，用有效访问令牌和 Bearer。v1 Chat Completions 的路径为 /openai/v1/chat/completions。Azure OpenAI 鉴权 · Microsoft Entra ID
  • DeepSeek、硅基流动、智谱 GLM、OpenRouter、Groq、Together AI的官方 Chat Completions 都要求各自的有效 API Key，使用 Bearer。DeepSeek · 硅基流动 · 智谱 · OpenRouter · Groq · Together AI
  • DeepSeek Anthropic 兼容接口也要求有效的 DeepSeek API Key，支持 Bearer 或 x-api-key。选择 Claude Messages 格式时，可用根地址 https://api.deepseek.com 和覆盖路径 /anthropic/v1/messages。DeepSeek Anthropic 兼容接口
  • Kimi、火山方舟（豆包）、阿里云百炼（千问）的 OpenAI 兼容 Chat Completions 使用各自的有效 API Key 和 Bearer。Kimi · 火山方舟 · 阿里云百炼
  • Ollama Cloud直连 ollama.com 时必须提供有效的 Ollama 密钥。OpenAI 兼容接口和托管的 Anthropic 兼容 Messages 接口都使用 Bearer。Ollama Cloud 鉴权

插件如何发送

可手动指定 Authorization: Bearer、x-api-key、x-goog-api-key、api-key 或 URL 查询参数 key，再把原始密钥填进 API Key。Bearer 前缀由插件添加。

自动模式优先使用你已配置的上述鉴权头或 key 查询参数。自定义其他凭据时，选择「手动或无需鉴权」，并按服务要求填写额外请求头或查询参数。
